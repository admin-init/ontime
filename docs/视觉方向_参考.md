# 视觉方向参考（来自 baoyan-demo 的 UI 修订 prompt）

> 用途：本轮「到点」前端改版的视觉基准。原文来自另一个项目，**只取视觉语言与"减少容器"的方法**；
> 其中「资料板块」「案例板块」「模拟面试」等业务要求不适用于到点。
>
> **到点配色修正（优先于下文 baoyan 的杏桃橙）**：品牌色用深墨绿 `#1D4A3B` / `#143A2E` / `#E4EDE7`，
> 杏桃橙不采用。状态点：已支持 `#4C8B6E`、已确认 `#1D4A3B`、冲突 `#B45B3E`、待确认 `#A19D95`。

## 明确采用的视觉方向

弱化"AI 产品模板感"，轻盈克制的早期 iOS 式半透明质感：

- 浅色背景；
- 微弱磨砂、细腻透明度；
- 柔和层次、纤细分割线；
- 自然圆角、清爽字体；
- 低饱和点缀；
- 整体轻松、自然、通透、极简。

"早期 iOS 式"只描述轻量半透明和干净层次，不是复刻某个系统版本，也不引入 iOS UI 框架。

毛玻璃只在少量确实需要层次的区域使用（顶部导航、浮层）。其余区域保持干净实色。

**明确避免**：Material 式厚重卡片与悬浮、厚重拟物、炫彩渐变、强烈模糊、发光描边、满屏玻璃卡片、为通透牺牲文字对比、给每个按钮/标签/模块都套圆角容器。

## 减少框线和卡片套卡片

保留功能与入口，允许调整布局。优先用这些手段区分模块：

- 留白、间距、对齐、字体层级；
- 轻微底色变化；
- 必要的细分割线。

能不框起来的内容就不框；不要只把旧卡片边框变浅，内部仍保留三四层嵌套容器。

允许：移除无作用的外层卡片、合并重复标题与说明、简化大面积状态条和标签组、调整内容宽度与区域比例、把卡片列表改成更轻的条目列表。

不允许：新增营销首页、隐藏主要入口、破坏现有流程、删信息换极简、为布局重写服务端或状态。

## 浮层与导航

- 可以少量使用轻度半透明；
- 必须有实色降级，不依赖模糊才能看清；
- 不在每条消息或长列表条目上叠加 backdrop blur。

## 验证重点（录制 Demo）

- 桌面录制尺寸下的整体观感；
- 内容是否还被过多方框分割；
- 页面是否明显溢出或截断；
- 关键操作是否容易找到；
- 窄屏是否破版；
- 半透明区域是否仍清楚可读。

## 对照到点的取舍

| baoyan 的做法 | 到点怎么用 |
|---|---|
| 用留白和分割线替代卡片 | 字段表天然适合：一行一字段 + 细分隔线，不要每行一个卡片 |
| 顶栏轻半透明 | 直接采用，但滚动时保持文字对比 |
| 低饱和小面积点缀色 | 状态点（支持/冲突/待确认）用低饱和绿/橙/灰，不用色块 |
| 把卡片列表改成轻条目 | 收件箱、任务清单、历史时间线都用条目式 |
| 不满屏玻璃 | 只有顶栏和来源浮层用模糊，其余实色 |
| 不用粗重标题 | 页面标题 20–24px/600，区块标题 13–14px/500 + 字色变化 |

**到点独有、不能省的东西**：字段级来源（点开看原文）、冲突并排候选、状态点、历史只追加。这些必须保持可见，只是用更轻的方式表达。
