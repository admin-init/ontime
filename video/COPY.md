## 1. 105 秒宣传片

### 1.1 旁白（VO）

> 语速：中文 4.2–4.6 字/秒；句间留 0.3–0.5 秒；不要压着画面切换抢字。

| 时间 | 旁白 |
|---|---|
| 0:00–0:05 | 官网一条，邮件一封，群聊一句。每一条都看到了，合起来还是拼不完整。 |
| 0:05–0:12 | 到点把官网、邮件、聊天截图，汇到同一个事件里。先看见，再确认。 |
| 0:12–0:15 | 到点：把碎片，拼成一件有依据的事。 |
| 0:15–0:24 | 一张截图，变成一件要做的事。识别出活动时间、报名截止和待办，每一项都能点开看原文。 |
| 0:24–0:40 | 活动时间和报名截止，是两个字段；各自带着自己的出处。收进收件箱，确认后才生效。 |
| 0:40–0:53 | 第二份信息进来，不是覆盖，是并列。旧值、新值、来源，并排给你。 |
| 0:53–1:04 | 合并不是自动的，由你决定。两种说法，你选一个，另一种留在历史里。 |
| 1:04–1:16 | 能核实的，给出官网原文；来源、域名、检索时间，都在画面里。 |
| 1:16–1:24 | 找不到明确依据的，就写未确认。不编规则，也不给结论。 |
| 1:24–1:35 | 最后落到一张清单：什么时候做，要带什么，依据在哪。勾掉一项，倒计时继续；需要时导出日历。 |
| 1:35–1:41 | 官网、邮件：入口已在，自动接入尚未启用。未来，用户授权下的指定网站查询。 |
| 1:41–1:45 | 到点。把散落的信息，变成有据可查的行动。 |

## 2. 约 4 分钟流程片

### 2.1 旁白 / 字幕

| 段落 | 旁白 |
|---|---|
| F01 开场 | 同一个事件，常常来自三个地方：官网、邮件、聊天截图。当前 Demo 以截图收录为主；官网和邮件保留入口。 |
| F02 复位 | 每次拍摄，从空状态开始。 |
| F03 第一张截图 | 第一张截图，是一份公开讲座通知。拖进来，系统开始识别截图、整理事项、查找关联事件。 |
| F04 确认与字段 | 结果先到收件箱，不自动生效。活动时间、报名截止、地点，各自成字段；点开“报名截止”，能回到原文和来源。 |
| F05 第二张截图 | 第二张截图，是班级群聊。群聊说地点改了，还补了一份材料。 |
| F06 关联与冲突 | 系统提出合并建议，但不自动合并。旧值、新值、来源并排；地点有两种说法，你选一个，另一种留在历史里。 |
| F07 材料与待确认 | 这条材料只来自群聊，没有官方依据；相对时间没有锚点，标为待确认。不编造，也不覆盖。 |
| F08 联网核实 | 点“联网核实”，真实检索公开网页并对照原文。找到的，显示来源、域名、检索时间；找不到明确依据，就写未确认。 |
| F09 行动清单 | 回到行动台，任务按截止时间排好。勾掉一项，计数跟着变；需要时导出日历。 |
| F10 来源追溯 | 每个字段都能回到原文；历史只追加，不覆盖。 |
| F11 边界与规划 | 设置页写清能力边界：官网、邮箱是入口，自动接入未启用；自定义网站查询是规划能力。 |
| F12 收尾 | 到点。把散落的信息，变成有据可查的行动。 |

### 2.2 屏幕上必须出现的固定文案

- 收件箱空态：「新收录的内容先到这里：确认无误才进入行动台，合并与覆盖都由你决定。」（页面原文）
- 处理中：「识别截图 → 整理事项 → 查找关联事件 → 等待确认。」（页面原文）
- 冲突：「同一字段有两种说法。选择一种保存，另一种仍会留在历史里。」（页面原文）
- 核实中：「正在检索公开网页并核对原文…」（页面原文）
- 未找到：「未找到明确适用的官方依据。没有给出任何结论。」（页面原文）
- 设置页：「已接入的标「已实现」，没接入的明确写「演示暂未接入」。」（页面原文）

## 3. 字幕方案

### 3.1 建议

- **主片与流程片都用中文单语字幕**。目标评审是中文环境，双语会挤占画面、降低可读性。
- 如果确认有国际评审，再额外提供一份 **英文 SRT**（不烧进画面），或做“中英双行”版本：中文 32px、英文 20px，行距 1.25。不要在 105 秒里默认双行。
- 字幕文件：`video/subtitles/promo.zh.srt`（105 秒草稿）、`video/subtitles/flow.zh.srt`（4 分钟草稿）。UTF-8 无 BOM。
- 每行不超过 **18 个中文字符**，最多两行；单条 2–5 秒；不要跨镜头断句。
- 位置：底部居中，距底 80px；如果画面底部有任务列表/导出按钮，字幕上移到 120px，或改为左下角。
- 样式建议：Noto Sans SC Medium / 34–38px；白字 + 60% 黑色半透明底；圆角 8px；不要描边发光。
- 烧录命令见 `FFMPEG.md`；原始 SRT 与烧录版同时保留，方便改字。

### 3.2 英文术语（如做英文版）

| 中文 | 英文 |
|---|---|
| 字段级溯源 | field-level provenance |
| 不静默覆盖 | no silent overwrite |
| 未确认 | unconfirmed / not verified |
| 合并建议 | suggested merge |
| 冲突 | conflict |
| 行动清单 | action list |
| 官网同步 | website sync |
| 邮箱接入 | email connection |
| 自定义网站查询 | custom site lookup |
| 规划能力 | planned capability |

### 3.3 TTS / 真人

- 先用 TTS 锁时长：建议 `zh-CN-YunxiNeural`（男声，稳）或 `zh-CN-XiaoxiaoNeural`（女声，亲和）；语速 1.0，句间 0.3s。
- TTS 生成后逐段 `ffprobe` 量时长，回填 `SHOTLIST.md` 的时间；不要反过来让画面硬卡 TTS。
- 最终如有真人配音，保留同一份 SRT，只替换音轨；字幕时间以最终音轨为准。
- BGM：90–105 BPM、无 vocals、钢琴/lo-fi；旁白下 duck 到 -18 dB；终混 -16 LUFS、TP -1.5 dBTP。未选曲前不要先铺满 BGM。
