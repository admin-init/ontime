## 时间线上的选择

- **叙事不是功能罗列。** 3–13s 先给三份碎片；13–21s 把「连回原文」作为全片论点；之后每一段都在证明它：字段能回到原文、合并只给建议、找不到就说没找到、行动清单有出处。
- **加速段是硬要求。** 02 通知收录 8×（4.25s，标「×8 实际约 30 秒」）；07 检索 1.35×（4.67s，标「×1.4 实际检索约 5 秒」）；08 链接核对 2.2×（3.97s，标「×2.2 实际约 7 秒」）。05 群聊收录 16×（3.1s，标「×16 实际约 49 秒」），否则 130 秒放不下。
- **多来源段（98–119.35s）。** 官网二次同步实际 3 秒（1×）；邮件解析实际 23.7 秒，用跳切压到 3.9 秒并标「×6 实际约 24 秒」；Agent 调研实际 10.2 秒（表单 2×、结果 1.15×），结果给出 5 条真实条目和「写入并替换当前规则」。
- **慢放也标。** 06 diff / conflict 0.5×、04b 材料 0.7×、09 历史 0.54×、行动台 0.92×，都在顶栏写了「0.5× 慢放」这类真实说明，不把慢放当实时。
- **推近只做 scale + translate。** 03 确认按钮、04 活动时间与来源缩略图、04b 报名截止/材料、06 diff 与地点两候选、07 未找到横幅、08 findings、09 任务区/历史、多来源设置页与能力矩阵；倍率 1.15–1.75，缓动 `bezier(0.33,0,0.2,1)`。
- **标注是编辑层，不是 App UI。** 2.5px 细线框 + 23px 说明（比 30px 字幕小一号），颜色只用项目色；不伪造按钮、不伪造 toast、不把绿色状态点解释成官方认可。

## 已知问题在剪辑里的处理

| 问题 | 处理 |
|---|---|
| 标题冲突（群聊把标题抽成「讲座」） | 冲突镜头只框地点两候选；diff 保留标题行但不给特写；历史屏不强调标题条目 |
| 导出无 toast | 不 P 提示；用真实 `.ics` 文件卡（795 B），并写「页面暂无提示；文件已生成」 |
| 行动台计数 0 vs 2 | F1 推近任务区，裁掉事件行徽标；只讲勾选与未完成清零，不改数字 |
| 08 findings 屏含真实冲突提示 | 保留红条，用「只标出，不覆盖」解释；不后期改绿 |
| 6 条 findings 只拍到 2 条 | 角标「本屏 2 条 / 共 6 条」；不伪造滚动 |
| 通知没有材料清单 | 材料镜头明确写「群聊来源 · 非官方通知」，不归因给通知 |
| 日历没有真实手机截图 | 日历卡标「日历示意」，不冒充截屏 |
| 官网 UNNC 活动栏目有 1 条抽取失败 | 保留失败行，标「1 条抽取失败 · 保留」；不剪成全部成功 |
| 站内提醒有重复条目（多次邮件导入造成） | 保留真实列表，首条为主；不删数据 |
| 邮件解析实际 23.7 秒 | 跳切到已处理行，标「×6 实际约 24 秒」；未展示静态处理中行 |
| Agent 按钮实际文案 | 为「写入并替换当前规则」，未点击；规则待确认 |
