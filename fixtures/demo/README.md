# Demo 素材：到点 · 录屏用截图

本目录是「到点」Demo 录屏（3–5 分钟）用的输入素材。三张 PNG 分别扮演三个不同来源：
一张**真实公开通知**的截图、一张**班级群聊**截图、一张**同一通知的补充说明**截图，
用来演示「同一字段出现新值时并列展示、由用户确认」以及「未确认就说未确认」。

所有图片均由 `generate.py` 用 Pillow 渲染，文字是真实排版的矢量文本（非模糊占位），
字号在 1x 下不小于 15px。

---

## 1. 文件清单

| 文件 | 用途 | 是否自拟 | 对应文字稿 |
| --- | --- | --- | --- |
| `notice.png` | **正式通知截图**。演示"官网通知"这一来源，抽出活动名称、活动时间、截止时间、地点、材料、提交方式 | **非自拟**（依据真实公开通知绘制） | `notice.txt` |
| `chat.png` | **班级群聊截图**。演示"聊天记录"这一来源，制造与通知冲突的地点与材料 | **自拟**（虚构人名与对话） | `chat.txt` |
| `notice_2.png` | **同一通知的补充说明截图**。演示"官方补充说明"这一来源，用于演示冲突如何被官方口径确认/变更 | **自拟**（不存在对应的真实公开通知） | `notice_2.txt` |
| `notice.txt` / `chat.txt` / `notice_2.txt` | 对应图片中文字的**逐字内容**，供流水线/OCR 结果对照 | — | — |
| `generate.py` | 生成脚本。改文案或字号后重跑即可再生全部图片与文字稿 | — | — |

重新生成：

```powershell
cd backend
uv sync
.\.venv\Scripts\python.exe ..\fixtures\demo\generate.py
```

> 脚本会同时重写 PNG 与 `.txt`，两者不会失步。

## 4. 拍摄时的使用顺序

1. **第一张：`notice.png`** —— 拖入"官网/通知"来源。演示系统从真实通知里抽出
   活动名称、时间、截止、地点、材料、提交方式，并让每一个字段都带上原文出处。
2. **第二张：`chat.png`** —— 拖入"聊天记录"来源。演示系统发现：
   - 地点出现**第二个值**（鼎新楼报告厅）→ 与通知里的值**并列展示，不静默覆盖**，由用户确认；
   - 材料出现**新的一项**（一页项目介绍）→ 单独列出来源，不并入旧材料；
   - 截止时间只是群友的**疑问**，没有新值 → 保持原值，并显示"未找到明确适用的官方依据"。
3. **第三张（可选）：`notice_2.png`** —— 演示官方补充说明到达后，
   地点/材料/截止时间三个字段被**官方口径确认或变更**，用户确认后才更新，
   且更新可撤销。若录屏时间紧张，这张可省略，只保留前两张。

录屏顺序建议：**notice.png → chat.png →（可选）notice_2.png**，
与本目录中 `notice.png`、`chat.png`、`notice_2.png` 的编号一致。

## 5. 脱敏与合规说明

- `notice.png` / `notice_2.png` 均为**白底正式通知**版式；页脚有"演示素材"小字，
  避免被误当作原始网页截图。流水线对照时可忽略 `.txt` 的最后一行页脚。
- 原文中的**联系人姓名、办公电话、收件邮箱**均未出现在素材中；
  提交方式写成"收件邮箱见通知原文"，既保留语义又不泄露具体信箱。
- `chat.png` 中的人名、群名、对话全部虚构，无真实头像、手机号、学号、身份证号。
- 素材中出现的"吉林大学""党委学生工作部"及"鼎新楼C328多功能会议室"来自公开网页，
  属公开机构信息；`notice_2.png` 中的"鼎新楼报告厅"为演示用自拟值，页脚已标注自拟。

## 6. 已知限制

- `notice.png` 的事件日期（2026-10-26/27）早于本次抓取日期（2026-11-08）：
  它是**真实的历史通知**，不是"当天正在发生的通知"。录屏时如系统显示"已截止"，
  属预期结果，可顺势说明"历史通知也能被完整解析并留痕"。
- 演示时若要做联网核实，可直接用 <https://xsc.jlu.edu.cn/info/1048/5974.htm>
  核对 `notice.png` 的每一个字段（学校、发文单位、标题、时间、地点、材料、截止时间）。
